# Separate-profile native acceptance

Use only a disposable absolute folder and the locally built Windows EXE. Launch `ActiveRest.exe --data-directory <absolute-test-folder>`. A default launch accesses the normal profile and is not part of this procedure. Record the tested commit, Windows version, EXE/ZIP hash and the normal stats/settings/Run-entry hashes before and after using separate OS/file tools; do not put normal process names or registry contents into public evidence.

1. Open the main window. Its title must say **separate profile**, tracking must be off, and Settings must display the supplied folder. **Start with Windows** must be unchecked and disabled. Save a changed reminder interval and Monday/Sunday preference, reopen Settings, and check the same values; only the test-folder settings may change.
2. Press **Start tracking** once and keep a disposable editor foreground for several seconds. Focus time/process totals must increase. **Pause tracking** must freeze totals while other controls are used. Resume, then open/close Details and Settings; the application must remain accessible on the taskbar.
3. Export JSON into the test folder. Check daily totals and process names against the observed session. The export is private test evidence, not a productivity metric.
4. For date/week checks, close the app and seed only this disposable profile with readable daily records for 29 Dec 2025, 4 Jan 2026, 5 Jan 2026 and 11 Jan 2026 (focus values 10, 20, 40 and 80 seconds respectively). Launch again with the same argument. Select 4 Jan 2026 and Week: Monday start should give **30 seconds**, Sunday start **60 seconds**. Switching the setting must change the open report without restarting. Repeat with tr-TR/en-US if the device allows changing the application culture safely.
5. Export the selected report to a test-folder PDF. Open it independently and verify date/mode, totals, process table and legibility. The direct service test is not evidence that the native picker/export interaction passed.
6. Choose **Delete history**, cancel once, then confirm. On confirmation tracking must be off and the test-folder main history/backup must be gone. Exit/reopen must not recreate a record until Start is pressed. Exports and `.corrupt-*` recovery copies remain separate.
7. In a second disposable profile, use incomplete or future-format history/settings. The UI must show recovery guidance and leave originals unchanged. Start must not overwrite unreadable history; Delete/Save must report refusal. Repair requires a manual backup/repair and app restart.
8. Close the main window and test the tray **Safe Exit** path separately. The process and tracking timer must stop, readable live data must be saved, and the normal profile/Run-entry hashes must stay unchanged. Real sleep/awake or a true wall-clock midnight remains separate from synthetic rollover tests.

The profile switch is data separation, not an OS sandbox or new Windows user. Registry startup for the normal profile, fresh-machine install, real sleep/midnight, accessibility scaling and actual eye-reminder timing still need their own native evidence. Do not mark these checks passed merely because the package built or a synthetic-activity test passed.
